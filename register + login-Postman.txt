LOGIN E CRUD - POSTMAN

Base URL: http://127.0.0.1:5000

IMPORTANTE SOBRE O TOKEN
1. Execute o login.
2. Copie somente o valor de access_token da resposta.
3. No Postman, abra Authorization, escolha Bearer Token e cole somente o token.
   Nao escreva "Bearer " dentro do campo Token; o Postman adiciona isso sozinho.
4. Para conferir manualmente, o header enviado deve ser:
  Authorization: Bearer <Token Aqui>

----------- CADASTRAR USUARIO ----------------

POST http://127.0.0.1:5000/users/register

Body > raw > JSON:
{
  "username": "testuser",
  "password": "senha123"
}

Tambem funciona: POST http://127.0.0.1:5000/users/

----------- LOGIN -----------------------------

POST http://127.0.0.1:5000/users/login

Body > raw > JSON:
{
  "username": "testuser",
  "password": "senha123"
}

Resposta esperada:
{
  "access_token": "..."
}

----------- USUARIO LOGADO (/me) ---------------

Todas as requisicoes abaixo exigem Authorization > Bearer Token.

GET http://127.0.0.1:5000/users/me

PUT http://127.0.0.1:5000/users/me

Body > raw > JSON:
{
  "username": "testuser_novo",
  "password": "senha456"
}

DELETE http://127.0.0.1:5000/users/me

----------- USUARIO POR ID ---------------------

GET http://127.0.0.1:5000/users/1
PUT http://127.0.0.1:5000/users/1
DELETE http://127.0.0.1:5000/users/1

GET, PUT e DELETE exigem token. No PUT, use um body como:
{
  "username": "testuser_novo"
}

----------- FORMULARIO -------------------------

POST http://127.0.0.1:5000/formularios/

Authorization > Bearer Token

Body > raw > JSON:
{
  "nome": "Joao da Silva",
  "email": "joao.silva@example.com",
  "data_nascimento": "1990-01-01",
  "cpf": "12345678900",
  "genero": "Masculino"
}

GET http://127.0.0.1:5000/formularios/1
PUT http://127.0.0.1:5000/formularios/1
DELETE http://127.0.0.1:5000/formularios/1

GET, PUT e DELETE exigem token. No PUT, use um body como:
{
  "nome": "Joao da Silva Atualizado"
}


1. Execute GET, PUT e DELETE sem Authorization.
   Resultado esperado: a API bloqueia com status 401.

2. Execute uma operacao com token valido.
   Resultado esperado: a API permite a operacao.

3. Consulte um ID inexistente, por exemplo:
GET http://127.0.0.1:5000/users/999
GET http://127.0.0.1:5000/formularios/999

Resultado esperado: status 404 e mensagem informando que o registro nao foi encontrado.
